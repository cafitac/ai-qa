## Goal and scope

- Outcome: on the MacBook, `aiqa run <env>` runs the natural-language scenarios stored in the service repositories against a READY preview-hub environment through an agent CLI driving a real browser, and writes a `qa-report/v1` report with evidence; an unready environment or an expired session is refused before any agent call.
- Target user: the owner (cafitac).
- Hypothesis: one bounded agent call per scenario plus a runner-side verdict gate gives trustworthy PASS/FAIL results without metered APIs.
- Non-goals: PR-diff scenario proposals (Q2), VM container / PR comment trigger / service token / preview-hub changes (Q3), parallel scenario execution, Aside or other drivers, any paid service, any Earlypay code or configuration.

- Primary success evidence: unit tests per unit; live run on the example environment with two scenarios PASSED (B1); live run on an environment built from the deliberately broken backend branch with add-note FAILED and the other scenario PASSED (B2); refusal checks (B3); secret scan of the live run directory (B4); cap behaviour (B5); 2-of-2 clean reviews and green CI per unit.
